# Solution: LP-0018 — OpenStreetMap integration (decentralized map data distribution)

## Summary

A complete **fetch → store → register → verify → download** pipeline for
OpenStreetMap extracts: Geofabrik PBFs are mirrored into **Logos Storage**
(content-addressed) and registered on a **LEZ on-chain registry** whose
per-region records carry the Geofabrik-published MD5 next to the storage CID —
so consumers discover and download authentic map data from the Logos network
with verifiable provenance, without trusting a single operator.

Three deliverables in this repo, all building from source:

- a reusable **OSM SDK + registry module** (`osm-sdk`, crate `logos-osm`;
  region set, Geofabrik client, storage client, LEZ program client, FFI);
- the **OSM registry LEZ program** (`methods/osm`, RISC0 guest; batch
  registration; append-only mirror history);
- a **Basecamp app** (`module/` Qt plugin over the SDK cdylib + `app/` QML,
  registrar and consumer flows) plus a CLI (`cli/`) driving the same facade.

The on-chain lifecycle is proven live on a standalone LEZ sequencer with real
proofs (`RISC0_DEV_MODE=0`), and the off-chain lifecycle against a **real
Codex storage node** — both in `scripts/demo.sh` and in CI.

## Approach

**Closed region set as code.** The 72-region non-overlapping partition
(48 countries + 24 subregions; `us`/`india`/`china`/`russia` decomposed into
their Geofabrik sub-files under top-level parents) is frozen in
`methods/osm-core/src/set.rs` **and embedded in the guest program**. The chain
itself rejects any path outside the set, and `parent`/`level` on-chain come
from the embedded table, never from the client's claim — the partition
invariant is enforced by the verified program, not by client discipline. A
unit test pins the invariant that no decomposed country file is itself in the
set (hosting `us` would overlap the 8 states that are).

**Version discovery where Geofabrik actually publishes it.** There is no
version column in the index; the snapshot date is recovered per region from
the `X-Derived-From` response header of the `.md5` endpoint (primary —
present even when the body names the undated `-latest` file) or a dated
filename inside the `.md5` body, normalized to `YYYYMMDD`. Both paths are
exercised by a hermetic fixture server speaking Geofabrik's exact wire
format, so CI proves version logic without network egress.

**Integrity = Geofabrik's published MD5, anchored on-chain.** A host
verifies the downloaded bytes against the published MD5 **before** storing;
the checksum and the storage CID are both recorded on-chain. A consumer
fetching by CID re-verifies the same MD5 — a mismatch is a hard error, never
a silent pass (tamper-rejection is an explicit test). MD5 is weak as a
collision primitive but it is *Geofabrik's published checksum*: verifying
against it proves the bytes are what Geofabrik published, which is the claim
that matters (see `docs/DESIGN.md` §3).

**Registry model.** One RISC0 guest; accounts are PDAs — one registry PDA
(counters, owner) + one PDA per region (`SHA-256("osm-region:" || path)`).
Each `RegisterRegion` **appends** a `Mirror { registrar, cid, checksum,
version, timestamp, hosted }` to the region entry; history is
timestamp-ordered (version sorting) and capped at 32 (oldest pruned).
Registration is **permissionless** — the adoption criteria measure
independent registrars, so owner-gating would defeat them. `source_url` from
the A.2 schema is derivable, not stored: the embedded table maps every region
path to its canonical Geofabrik URL, so the chain stores the unique key
(`region`) and the URL is a pure function of it. `RegisterRegionsBatch`
(1–24/tx) amortizes one registry write + one registrar nonce over N regions
for bulk hosting; the CU profile measures the amortization.

**Wallet boundary.** The SDK **builds** registration transactions (accounts +
risc0-serde instruction words, JSON) and the wallet **submits** — the SDK
never holds keys. The full submit path is proven by
`tests/tests/osm_registry_live.rs` against a real standalone sequencer:
deploy → `Init` → **germany registered by 3 distinct registrars with
advancing versions (20260801 → 20260815 → 20260821, append-only)** →
`RegisterRegionsBatch { france, us/california, kenya }` → on-chain counters
read back (region_count=4, registration_count=6).

**Transport-agnostic SDK.** `Storage` trait with `CodexStorage` (real REST
node, streaming) and `MemoryStorage` (offline); a `mirror()` host-swap lets
the same client code run against the hermetic fixture server in CI and the
real Geofabrik in production. Transient failures (connection errors,
timeouts, 5xx, 429, 408) retry with exponential backoff and surface a clear
error only after exhaustion (`retry.rs`, unit-tested).

## Success Criteria Checklist

### Functionality
- [x] **Region discovery** — `osm discover` / `discover()`: fetches
      Geofabrik's `index-v1-nogeom.json`, joins URL-first against the frozen
      table, and returns the closed set with PBF URL, level
      (country/subregion) and parent; the live index must resolve **all 72**
      (asserted in tests). `osm regions [--parent us] [--level country]`
      lists the tree.
- [x] **Host workflow** — `host_region`: download (streaming) → verify
      against the published MD5 → store in Logos Storage → snapshot ready to
      register (checksum + version). CLI: `osm host <region> --registrar`
      also prints the LEZ tx.
- [x] **Download workflow** — `fetch_snapshot(region, cid, checksum)`:
      Logos Storage first (streaming), **Geofabrik direct fallback** if the
      region isn't hosted; either source must match the on-chain checksum.
- [x] **Checksum verification** — streaming MD5 of the download verified
      against Geofabrik's published checksum; mismatch = hard error. Verify
      without a full download is the `.md5` fetch (`update_check` does
      exactly this — version + checksum from a ~100-byte file).
- [x] **Bulk host with opt-out** — `host_regions_bulk(regions, opt_out)` /
      `osm host-bulk --regions all --opt-out russia/moscow,...`; skipped
      regions are reported, a failing region doesn't abort the run. Selection
      stays inside the non-overlapping closed set by construction (the set
      *is* the partition), so the overlap-warning clause doesn't arise —
      enforced again by the guest rejecting out-of-set paths.
- [x] **Local import** — `osm import <region> --pbf <file> --registrar <hex>`
      runs the full workflow: structure-validate the PBF → **verify its MD5
      against Geofabrik's currently published checksum** (a stale local file
      is refused, not registered) → store in Logos Storage → print the
      registration tx. Without `--registrar` it catalogs locally
      (offline-friendly).
- [x] **Update check** — `update_check` / `osm update`: fetches only the
      `.md5` (version + checksum), compares per-region on the region path
      (country vs subregion tracked independently), and reports
      UpToDate / UpdateAvailable / NotImported. Hermetic test proves the
      transition when upstream publishes a newer snapshot.
- [x] **On-chain registry program** — stores per-region entries with
      `region` (unique Geofabrik path), `parent`, `level`, per-mirror `cid`,
      `checksum`, `version`, `hosted`, `timestamp` (+ `registrar`;
      `source_url` derived from the embedded table, see Approach). Queryable
      **by region** (region PDA read), **by parent** (`children_of`),
      **by CID** (`mirror_by_cid`); batch registration supported
      (`RegisterRegionsBatch`).
- [x] **OSM registry module** — the SDK is a self-contained crate
      (`logos-osm`) reusable by any Logos app (no dependency on the
      Basecamp app); the Qt module plugin (`module/`) wraps it over a C ABI
      so other modules can do the same.

## Adoption (informational)

The registry's on-chain schema is the adoption ledger: distinct registrars
per region, version advancement over time, and coverage are all read
directly from region accounts (`RegionEntry::registrars`,
`latest_mirror().version`). Seeding registrations is a plain
`osm host --registrar …` + wallet submit per region; the marathon window
starts at the first on-chain registration.

## Notes for reviewers

- **Why MD5**: it is Geofabrik's published checksum — verifying against it
  proves *the bytes Geofabrik published*; substituting SHA-256 would
  self-attest bytes of unproven provenance. The on-chain pairing of
  (CID, MD5, version) is what makes a mirror auditable.
- **Permissionless registration is deliberate** (adoption = independent
  registrars). There is no removal instruction — registrations are
  append-only; a wrong mirror is superseded by `latest_mirror()`, not erased.
- **Committed guest artifact**: CI embeds `osm_registry.bin` (no risc0
  toolchain needed for unit jobs); bytes→program-id→docs consistency is
  asserted by a unit test.
